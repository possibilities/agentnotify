# Native notification inbox design

The person opens this panel to decide what still needs attention and take the next action. Content, read state, and completion lead; product identity and transport status do not occupy a rail.

## Visual language

A continuous semantic window surface, SF system typography, and grayscale controls. System appearance selects light and dark automatically. A functional category menu, count, search, filters, and a detach control occupy the top. The category’s custom chevron has an explicit 8-point gap; the count stays outside the menu label so AppKit does not compress the composition. Notification rows share a title/body/metadata/action alignment without enclosing cards. The selected row gets a subtle surface; every other boundary must earn its space.

Type roles: 20-point semibold category, 13-point semibold titles, 13-point regular body, 11-point metadata. Outer inset 20 points, row inset 10, restrained 6-point control radii, 28-point icon targets. Default inbox 440 × 610; the panel supports 360–700-point widths. Use semantic colors, never fixed light/dark overrides in production. Relative dates omit ticking seconds.

## Behavior

Inbox, Unread, Later, Done, and All are status views. Search matches title, subtitle, message, and group. Group filtering is exact; time filters use creation time. Long content expands in place. Reading does not complete or execute a callback. The same compact checkmark control used by arrival previews marks individual completion in the Inbox; on a Done item it reopens the notification. Every icon-only button and menu uses the same restrained rounded hover highlight while keeping the standard macOS arrow cursor. More → Complete All requires confirmation with the current Inbox count, then atomically moves every active Inbox notification to Done, closes unanswered prompts, and never runs callbacks; Later and history remain unchanged. Its global shortcut defaults to `⌥⇧⌘D` and can be changed or cleared in Preferences. Recording requires at least two modifiers; bare Escape cancels and bare Delete clears, while modified keys such as `⌃⌘Esc` can be assigned. Its handler opens the Inbox and the same count-aware confirmation instead of performing a silent bulk mutation. The individual confirmation names the completed notification and offers “Undo completion”; its close control only hides the confirmation. Feedback disappears after 60 seconds, and completing another notification starts a fresh 60 seconds for that item. Expiry changes no durable task state; Done remains available for later reopening. A native context/menu surface carries less frequent operations.

One action is a button; multiple actions form an Options menu; a reply expands an inline field. Explicit body callbacks have a distinct Open, Open App, or Run Action control. Their target is inspectable in details. A notification without a supplied action gets no fabricated primary action.

One nonactivating panel owns the hosting controller and model in both pinned and unpinned states. Hiding a window never changes task state. API/MCP `show` can select a notification and choose detached presentation.

Pinning preserves the content's screen coordinates and the toolbar's control positions; it changes only dismissal policy. The panel stays where placed and never follows menu-bar auto-hide. It uses a transparent borderless window with a continuous 20-point corner. Drag blank space anywhere on the panel to place it independently, including the header, margins, empty body, and space around or below notifications. The outer resize edge retains native resizing. Unpinning keeps the same window and position. Closing an unpinned inbox and opening it again positions it below the real status button, projected inside the display; there is no invisible anchor window. Close lives in More. The intact native status button owns pressed and selected rendering; selection is restored after opening and cleared after the panel is hidden. See [the native panel decision](adr/0003-native-status-panel.md).

Opening a panel does not automatically focus the category menu. Pointer input clears control focus while preserving an active text editor. Tab and keyboard menu navigation retain native focus indication; VoiceOver retains native focus behavior. Do not suppress every focus ring to make a surface quieter.

Dragging keeps one screen-space grab point for the whole gesture. Use the mouse event's global position and the captured starting window origin; converting queued window-local positions through an already moved window creates feedback and jitter. Explicit background drag surfaces own dragging, with native background dragging disabled. They sit behind interactive content, with a second surface inside the scroll view filling at least its viewport; controls, text input, and scrolling retain their normal behavior. Mouse-up or changing windows clears the gesture. This preserves the grab point through direction changes without tethering the panel to the menu bar.

An unpinned inbox closes on outside mouse-down or loss of key status; pinning disables both paths. Another app's menu-extra click dismisses it even if that app does not activate. Otherwise the inbox stays open under the pointer. After the pointer leaves the panel and tray icon, it dismisses after one second; returning cancels the countdown. Opening with the pointer elsewhere uses a longer five-second grace period, so an unvisited, unpinned surface still dismisses. Native menus pause dismissal, while text editing, keyboard navigation, and VoiceOver keep it open. A pinned panel never dismisses on pointer exit. Window tracking and local/global mouse events drive a one-shot delay, with no position tracking. Movement outside recovers a missed frame-exit event and returns control from keyboard navigation. Once the pointer leaves, continued outside movement does not restart the deadline. Returning cancels it; ending a sheet or text editing can resume it. Closing or pinning removes the event monitors and restores the window’s prior mouse-movement policy.

## Arrival previews

The compact arrival and durable inbox answer different questions: what just arrived, and what still needs attention. The default Queue Peek design is a 440 × 126-point peek into the inbox, with its semantic surface, SF type roles, and continuous 20-point outline. A subtitle (or group) identifies context, followed by the title and up to two message lines. The quiet footer leads with a burst’s scope when needed, then distinguishes unread notifications from read items that still need attention: “10 unread notifications” or “Latest of 3 arrivals · 10 unread · 2 read still need attention.” A shorter equivalent fits constrained styles rather than truncating the counts. The tray keeps the total unfinished count, capped visually at 99+ with the exact count and unread count in its accessible label and tooltip.

One nonactivating panel appears beneath the safe menu anchor and remains until the person dismisses it, opens the inbox, or completes its last item. It stays still while shown, and opening the inbox uses the captured anchor so an updated tray count cannot shift the handoff. It fades in for 160 ms; Reduce Motion removes the fade. The whole body opens the displayed notification, the small X only dismisses the preview, and the separate Complete control changes durable task state. Opening reads the item but never answers, completes, or runs an action. Finish the original mouse-up before opening the inbox panel.

Bursts update the same renderer and window; no preview stack forms. The latest arrival appears immediately unless a mouse button is actively down. During that press the displayed content and clicked identity stay frozen, then advance after mouse-up, so a click cannot open or complete a different item than the one pressed. The Complete activator uses the same durable `status done` transition as the full Inbox checkmark. It closes an unanswered prompt without executing callbacks, advances the shared preview to the next eligible burst item, and dismisses the surface after the last item. A failed or conflicting completion leaves the item visible. Group replacements stay durable. If a pressed lead was replaced, the click can still inspect that exact historical item; the full inbox owns current response availability. New arrivals while the inbox is open add a small cue inside it without moving the window, changing the current selection, or putting a second panel over it. Reading or using the cue clears it.

The durable `created` and `due` change events drive arrivals, with a launch cursor baseline. Read, delivery, reopen, and callback bookkeeping never replay arrivals. Eligibility is checked again against current state before presentation. AgentNotify's own preview is the sole arrival surface. The app does not request UserNotifications authorization or post macOS banners, sounds, categories, or Notification Center entries; Focus, screen sharing, remote control, and system notification presentation policy therefore do not govern arrivals. This inbox-only policy applies to both modern and terminal-notifier-compatible sends.

Debug `arrival-studio` opens a separate native controller and synthetic target. It compares Queue Peek with the smaller Compact Toast and queue-footer Queue Shelf alternatives, with single/burst/long scenarios and light/dark appearance. Studio selections are transient and do not change saved preferences. `render-arrivals <directory>` produces 18 actual SwiftUI renders. The studio is excluded from release builds.

The controller and target start beside each other; moving the controller or choosing Arrange windows reunites them. Design and scenario changes reveal the compact preview, while appearance changes update whichever surface is open. Show preview holds it for inspection; Replay arrival repeats the production fade and then leaves the preview in place. The controller reports the current presentation and disables redundant actions. Opening the inbox ends the preview, and sample completion/Undo updates its unread and waiting counts. Pinning controls the synthetic inbox's hover dismissal without moving it. Settings explains the synthetic boundary without leaving the studio. AppKit owns explicit hosting sizes so content updates cannot collapse or displace the borderless target.

To restore a person's transient choices after a debug rebuild, pass all three selections: `arrival-studio compact-toast burst light`. The optional tuple is design (`queue-peek`, `compact-toast`, `queue-shelf`), scenario (`single`, `burst`, `long`), and appearance (`light`, `dark`). This restores the comparison only; it does not adopt a production design or save a profile. Studio replay exercises the comparison surface, not system delivery or the production burst tracker.

## Preferences

More → Preferences opens a native, theme-following window. Appearance contains a segmented Arrival style picker: Queue Peek (default, 440 × 126), Compact Toast (360 × 96), and Queue Shelf (440 × 144). All three ship in production and use the same renderers as the labeled, noninteractive preview and debug studio. Preference changes apply to the next arrival; a visible target keeps its design and dimensions through the current interaction. One AppKit sizing owner keeps the window stable while content changes.

Preferences are stored separately from notification state, with a revision and conditional writes shared by CLI, socket, MCP, and GUI. Changing appearance neither completes a task nor adds a notification change event. A Terminal integration section offers Install shim (or Reinstall shim when already installed), its location, and the preserved original-notifier fallback. The Appearance composition stays unchanged above it.

Preferences contains no system-notification promotion, status, permission request, or System Settings link. The legacy `showBannerReminder` preference remains serialized only for API compatibility and has no visible or delivery effect. Removing banner delivery is a product invariant, not a presentation preference.

## Semantic interface control

The native UI and durable notification store are separate control planes behind one service. UI snapshots expose surfaces, filters, compact matching rows, exact selection, pin state, arrival state, an app-launch instance ID, and an in-memory UI revision. Voice and MCP clients operate those semantics directly; they never simulate coordinates or accessibility clicks. Relative navigation uses the UI revision to reject stale commands, and request IDs make retry-sensitive UI commands idempotent for the life of the app process.

Selection, expansion, navigation, presentation, filtering, and arrival dismissal are transient and never imply read, completion, response, or callback execution. Durable operations still require exact notification IDs and can use notification revisions. Mark All Read snapshots exact visible unread IDs and revisions and applies one atomic `statusBatch`. Headless services retain every durable operation but reject UI commands with `native_unavailable`.

The first inbox or Preferences opening offers terminal-notifier integration once, with Install shim and Not now. A new arrival never triggers the offer. Record its presentation durably before showing it; skipping, quitting, or a failed install must not create a recurring dialog. Already-installed fleet routers need no offer. The same button remains available in Preferences, with progress and visible installation errors. AgentStart owns the single shim installer, while AgentNotify owns this opt-in experience. Show the install location and PATH ordering because those determine which executable existing scripts reach; do not edit shell profiles or replace an unrelated command.
